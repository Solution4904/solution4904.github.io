# 💡 [32] RecyclerView
- 새로운 아이템 뷰를 반복적으로 인플레이션하는 대신 재활용하여 대규모 데아터 셋을 효율적으로 표시하도록 설계된 안드로이드 컴포넌트.
- ViewHolder 패턴으로 알려진 Object Pool과 유사한 메커니즘을 사용하여 효율적.


### 📑 내부 메커니즘 핵심 개념
1. 뷰 재활용 : 뷰가 보이는 영역 밖으로 스크롤되면 소멸 대신 ViewPool에 추가. 새 항목이 뷰에 들어오면 기존 뷰를 검색하여 인플레이션 오버헤드를 피함.
2. ViewHolder 패턴 : 반복적인 findViewById() 호출을 방지. 레이아웃 순회 및 뷰 조회를 줄여 성능 향상.
3. Adapter의 역햘 : 데이터 소스와 뷰를 연결하는 다리 역할. Adapter.onBindViewHolder()는 뷰가 재사용될 때 데이터를 뷰에 바인딩하여 보이는 항목만 업데이트되도록 보장.
4. RectycledViewPool : 사용되지 않는 뷰가 저장되는 Object Pool 역할. 유사한 뷰 유형을 가진 여러 목록 또는 섹션에서 뷰를 재사용하여 메모리 사용량을 더욱 최적화.


### 📑 재사용 메커니즘
1. 스크롤 및 항목 가시성 : 사용자가 스크롤하면 뷰 밖으로 나가는 항목은 분리되지만 소멸하진 않음. RecycledViewPool에 추가됨.
2. 재활용된 뷰에 데이터 리바인딩 : 새 항목이 뷰에 들어오면 RecycledViewPool에서 필요한 유형의 사용 가능한 뷰 확인. 일치하는 항목이 존재하면 onBindViewHolder()를 사용하여 새 데이터로 리바인딩하여 뷰를 재사용.
3. 사용 가능한 뷰가 없는 경우 인플레이션 : Pool에 접합한 뷰가 없다면 onCreateViewHolder()를 사용하여 새 뷰를 인플레이션.
4. 효율적인 메모리 사용 : 뷰를 재사용하여 메모리 할당 및 가비지 컬렉션 최소화.


### 📑 장점
1. 향상된 성능 : 뷰 재사용으로 새 레이아웃 인플레이션 오버헤드가 줄어들어 더 부드러운 스크롤과 성능을 제공.
2. 효율적인 메모리 관리 : Object Pool로 뷰를 재사용하여 메모리 할당을 최소화하고 빈번한 가비지 컬렉션 방지.
3. 커스텀 : 각 유형에 대한 최대 뷰 수를 관리하도록 커스텀 가능하여 개발자가 특정 사용 사례에 대한 동작을 최적화 가능.
