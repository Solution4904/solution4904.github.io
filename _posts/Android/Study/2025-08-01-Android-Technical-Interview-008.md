# 💡 [35] AppCompat 라이브러리

### 📑 주요 기능
- UI 컴포넌트 하위 호환성 : FragmentActivity 확장, AppCompatActivity와 같은 최신 UI 컴포넌트 제공.
- Material Design 지원 : Material Design 원칙 통합, 기기 별 API 레벨에 따라 모양과 동작을 자동으로 조정하는 위젯 제공.
- 테마 및 스타일링 지원 : 모든 API 레벨에서 일관된 UI 보장.
- 동적 기능 지원 : 동적 리소스 로딩 및 벡터 드로어블 지원을 제공. 최신 디자인 요소를 효율적으로 구현하기 쉽게 만듦.

# 💡 [36] Martial Design Components(MCD)란?
- Google의 Matrial Design 가이드라인을 기반으로 하는 커스텀 가능한 UI 위젯 및 컴포넌트 집합.


### 📑 주요 특징
- Material Theming : 테마 설정을 지원하여 개발자가 타이포그래피, 모양, 색상을 전역적으로 또는 컴포넌트 수준에서 커스텀할 수 있도록 함.
- 미리 빌드된 UI 컴포넌트 : 버튼, 카드, 앱 바, 내비게이션 드로어, 칩 등 즉시 사용할 수 있는 광범위한 UI 컴포넌트를 제공.
- 애니메이션 지원 : 모션 및 전환을 강조. 공유 요소 전환, 리플 효과, 시각적 피드백과 같은 애니메이션에 대한 내장 지원이 포함되어 UX 향상.
- 다크 모드 지원 : 다크 모드를 쉽게 구현할 수 있는 API가 포함되어 있음.
- 접근성 : 더 큰 터치 대상, 접근성을 위한 sementic 레이블 및 적절한 포커스 관리와 같은 기능을 제공.

# 💡 [37] ViewBinding & DataBinding
|*|ViewBinding|DataBinding|
|---|---|---|
|목적|뷰 접근 단순화|데이터 기반 UI 바인딩|
|컴파일 타임 클래스 생성|뷰에 대한 직접 참조 생성|뷰에 대한 직접 참조+내장 데이터 바인딩 기능이 있는 추가 클래스 생성|
|표현식|XML에서 지원X|XML에서 표현식+데이터 바인딩 지원|
|양방향 바인딩|X|O|
|성능|빠름, 오버헤드 적음|느림, 오버헤드 많음|
- 공통 특징
  - 타입 안전성 : 캐스팅할 필요 없이 뷰에 직접 접근하여 타입 불일치로 인한 런타임 오류 제거.
  - 더 깔끔한 코드 : findViewById()를 호출할 필요가 없어짐. 보일러 플레이트 코드가 줄어듦.
  - Null 안전성 : nullable 타입의 뷰를 자동으로 처리. 더 안전한 코드 보장.

# 💡 [38] LiveData
- 안드로이드 Jetpack 아키텍처 컴포넌트에서 제공하는 관찰 가능한 데이터 홀더 클래스.


### 📑 특징
- 생명주기 인식 : 컴포넌트의 생명주기를 관찰하고 활성 상태일 때만 데이터를 업데이트하여 크래시, 메모리 누수 위험을 줄임.
- 자동 정리 : 컴포넌트의 생명주기가 소멸될 때 자동으로 제거, 정리됨.
- 관찰자 패턴 : 관찰자를 활용하여 데이터가 변경될 때 자동으로 UI 업데이트.
- 스레드 안전성 : 스레드 안전하도록 설꼐되어 백그라운드 스레드에서 업데이트 가능.


### 📑 MutableLiveData & LiveData
||MutableLiveData|LiveData|
|---|---|---|
|차이점|setValue(), postValue()를 통해 데이터 수정을 허용.|수정 불가능|
|역할|외부에서의 직접적인 수정을 방지하기 위해 ViewModel 내에서 비공개로 유지.|읽기 전용 버전으로서 더 나은 캡슐화 보장.|

### 📑 setValue(), postValue()?
||setValue|postValue|
|---|---|---|
|스레드|메인 스레드|모든 스레드|
|동기화|즉시 동기적|비동기적으로 예약|
|사용처|UI 업데이트, 메인스레드에서 시작된 변경(사용자 상호 작용, 생명주기 기반 이벤트)|백그라운드 스레드 업데이트, 비동기 작업(데이터베이스 쿼리, 네트워크 요청, 장기적으로 실행되는 작업 등)|


### 📑 사용 사례
1. UI 상태 관리 : 데이터가 변경될 때 마다 UI가 자동으로 업데이트되어 인터페이스가 앱 상태와 동기화 되도록 보장.
2. 관찰자 패턴 구현 : LiveData는 발행자, Observer 인터페이스 구현이 구독자 역할을 하는 관찰자 패턴을 따름.
3. 일회성 이벤트 : one-off로도 사용 가능. 단 SingleLiveEvent 또는 유사한 구현으로 커스텀해야 가능.


### 📑 LiveData VS Flow
1. Flow는 안드로이드와 완전히 독립적인 API이며 안드로이드 컴포넌트에 대한 수명주기를 전혀 알지 못함. 따라서 구독 및 해지를 올바르게 하지 않으면 메모리 누수 가능성 높음.
2. LiveData는 구독 시점부터 생명주기에 따라 안전하게 데이터를 수집함.
