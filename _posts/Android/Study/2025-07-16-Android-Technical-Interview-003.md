# 💡 [9] Service란?
- 앱이 사용자 상호 작용과 독립적/장기적으로 작업을 수행할 수 있도록 하는 백그라운드 컴포넌트.
- UI가 없고 Foreground에 있지 않을 때도 계속 실행될 수 있음.
- 파일 다운로드, 음악 재생, 데이터 동기화, 네트워크 작업 등의 백그라운드 작업에 사용.


### 📑 Service 유형 간 차이점
|유형|백그라운드 실행|자동 중지|UI 알림 필요|
|---|---|---|---|
|Started Service|O|X|X|
|Bound Service|O|O|X|
|Foreground Service|O|X|O|

1. Started Service : 
> - 명시적으로 중지될 때까지 백그라운드에서 지속적으로 실행됨.
> - 백그라운드 음악 재생, 파일 업로드/다운로드

2. Bound Service : 
> - 안드로이드 컴포넌트가 Service에 바인딩할 수 있도록 함.
> - 바인딩된 클라이언트가 있는 동안 활성 상태 유지. 모든 클라이언트의 연결이 끊어지면 자동 중지
> - 원격 서버에서 데이터 가져오기, 백그라운드 블루투스 연결 관리

3. Foreground Service : 
> - 지속적인 알림을 표시하면서 활성 상태를 유지하는 특별한 유형의 Service.
> - 음악 재생, 내비게이션, 위치 추적 등 사용자가 계속 인지해야 하는 작업에 사용.


### 📑 Service와 Foreground Service의 차이점
|*|Service|Foreground Service|
|---|---|---|
|사용자 인지|사용자 모르게 백그라우드에서 실행 가능|알림이 필요함. 사용자가 작업이 진행 중이라는 사실을 알 수 있음.|
|우선 순위|낮음|높음|
|사용 사례|가벼운 백그라운드 작업|지속적이고 사용자가 인지할 수 있는 작업|


### 📑 Service 사용 모범 사례
- 즉시 실행이 필요하지 않은 백그라운드 작업에는 Service 대신 Jetpack WorkManager 사용
- 불필요한 리소스 소비를 방지하기 위해 작업이 완료되면 Service 중지.


### 📑 Service 생명 주기
- Started Service
  1. onCreate() : Service가 처음 생성될 때 호출. Service에 필요한 리소스 초기화에 사용
  2. onStartedCommand() : Service가 시작될 때 호출. 실제 작업 실행을 처리. Service가 종료될 경우 반환 값을 사용하여 재시작 동작을 결정.
  3. onDestroy() : Service가 중지될 때 호출. 리소스 해제나 스레드 중지와 같은 정리 작업에 사용.
- Bound Service
  1. onCreate() : Service가 샐성될 때 호출. 리소스 초기화에 사용
  2. onBind() : 컴포넌트가 Service에 바인딩될 때 호출. Service에 대한 인터페이스(IBinder) 제공.
  3. onUnbind() : 마지막 클라이언트가 Service에서 언바인드될 때 호출. 바인딩된 클라이언트에 특정한 리소스를 정리하는 데 사용.
  4. onDestroy() : Service가 종료될 때 호출. 리소스 정리 및 진행 중인 작업을 중지.

  > - Started Service와 Bound Service 생명주기의 차이점?
  > > 1. Started Service : 독립적이며 명시적으로 중지될 때까지 실행.
  > > 2. Bound Service : 최소 하나 이상의 클라이언트에 바인딩되어있는 동안에만 존재.

# 💡 [10] BroadcastReceiver란?
- 앱이 안드로이드 운영 체제 전체의 브로드캐스트 메시지나 특정 브로드캐스트를 수신하고 응답할 수 있도록 하는 컴포넌트.
- 배터리 상태 변경, 네트워크 연결 업데이트, 전송된 커스텀 Intent와 같은 다양한 이벤트를 알림.


### 📑 목적
- Activity나 Service의 생명주기에 직접적으로 연결되지 않을 수 있는 이벤트를 처리하는 데 사용.
- 백그라운드에서 계속 실행되지 않고도 변경 사항에 반응할 수 있는 메시징 시스템 역할을 하여 리소스를 절약.


### 📑 유형
1. 시스템 브로드캐스트 : 안드로이드 운영 체제에서 배터리 잔량 변경, 시간대 업데이트, 네트워크 연결/변경과 같은 시스템 이벤트를 앱에 알리기 위함.
2. 커스텀 브로드캐스트 : 앱에서 내부 또는 앱 간의 특정 정보나 이벤트를 전달하기 위함.


### 📑 사용 시 유의사항
- 생명주기 관리 : 동적 등록 시 메모리 누수를 방지하기 위해 리시버 등록을 해제해야 함.
- 백그라운드 실행 제한 : API26부터 registerReceiver 또는 JopScheduler를 사용해야 함.
- 보안 : 민감한 정보가 포함되는 경우 무단 접근을 방지하기 위해 권한으로 보호해야 함.


### 📑 사용 사례
- 네트워크 연결 변경 모니터링.
- SMS 또는 통화 이벤트에 응답.
- 충전 상태와 같은 시스템 이벤트에 대한 UI 업데이트.
- 커스텀 브로드캐스트로 작업 또는 알람 예약.
