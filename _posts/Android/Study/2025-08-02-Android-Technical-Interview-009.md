# 💡 [39] Jetpack ViewModel
- 생명주기를 인식하는 방식으로 UI 관련 데이터를 저장하고 관리하도록 설꼐된 안드로이드 앜텍처 컴포넌트의 핵심 구성 요소.


### 📑 특징
1. 생명주기 인식 : 생명주기에 범위가 지정됨. UI 컴포넌트가 더 이상 사용되지 않을 때 자동으로 소멸.
2. 구성 변경 간 지속성 : 상태를 유지하여 데이터 손실을 방지하고 데이터의 반복적인 리로드를 피함.
3. 관심사 분리 : UI 관련 로직과 비즈니스 로직을 분리하여 더 깔끔하고 유지 관리하기 쉬운 코드를 설계하는 데 도움.


### 📑 Jetpack ViewModel VS Microsoft MVVM ViewModel
||Jetpack ViewModel|Microsoft ViewModel|
|---|---|---|
|역할|비즈니스 로직 또는 UI 상태 홀더|View와 Model 간의 다리|
|기능|관련 비즈니스 로직 캡슐화, 상태를 관리하고 UI에 제공|View가 데이터 바인딩할 수 있는 속성과 명령을 구현, UI에 필요한 기능 제공, 변경 사항에 대한 알림 이벤트를 통해 View에 상태 변경 알림|
|장점|구성 변경 시에도 상태를 보유,유지해서 효율성, 응답성 향상|View가 상태 변경에 반응할 수 있도록 하는 바인딩 메커니즘을 강조하여 더 선언적이고 모듈화된 설계를 용이하게 함|
|목적|구성 변경 시 UI 관련 상태 유지|View와 Model 간의 중개자, UI가 ViewModel에서 제공하는 데이터를 표시하도록 보장|


### 📖 Question
1. ViewModel은 구성 변경 시 데이터를 어떻게 유지하며, onSaveInstanceState()를 사용하여 상태를 저장하는 것과 어떻게 다른가요?
2. ViewModelStoreOwner의 목적은 무엇이며, 동일한 Activity 내의 여러 Fragment 간에 ViewModel을 어떻게 공유할 수 있나요?
3. UI 상태 관리를 위해 ViewModel 내에서 StateFlow 또는 LiveData를 사용하는 것의 장점과 잠재적인 단점은 무엇인가요?

# 💡 [40] Jetpack Navigation 라이브러리
- 앱 내 내비게이션을 단순화하고 표준화하기 위해 안드로이드에서 제공하는 프레임워크.
- 선언적으로 화면 간 경로와 전환을 정의할 수 있도록 하여 보일러 플레이트 코드를 줄이고 전반적인 UX 향상.


### 📑 이점
1. 중앙 집중식 내비게이션 : 명확하고 유지 관리 가능한 구조를 위해 모든 내비게이션 흐름을 하나의 XML 에서 관리.
2. 타입-세이프 인수 : 생성된 Safe Args 클래스를 사용해 대상 간에 데이터를 안전하게 전달.
3. 백 스택 관리 : 일관된 내비게이션을 위해 백 스택 동작을 자동으로 처리.
4. 딥 링크 지원 : 외부 내비게이션 요청을 원활하게 처리하여 UX 향상
5. Jectpack 컴포넌트와의 통합 : Fragment, ViewModel, LiveData와 생명주기를 고려한 내비게이션 보장.


### 📖 Question
1. Jetpack Navigation 라이브러리는 백 스택을 어떻게 처리하고 NavController로 어떻게 백스택을 조작할 수 있나요?
2. Safe Arguments란 무엇이며, Jectpack Navigation Component에서 목적 내비게이션 간 데이터를 전달할 때 타입 안전성을 어떻게 보장하나요?

# 💡 [41] Dagger2 & Hilt
- 안드로이드 개발을 위한 의존성 주입 라이브러리.

|DI 라이브러리|Dagger2|Hilt|
|-|-|-|
|통합 프로세스|개발자가 컴포넌트와 인젝터를 수동으로 정의해야 하므로 많은 보일러 플레이트 코드를 작성해야 함.|사전 정의된 컴포넌트와 생명주기에 스코핑된 어노테이션 제공으로 이를 단순화함.|
|안드로이드 생명주기 통합|더 범용적. 생명주기 인식 컴포넌트에 대한 수동적인 설정 필요.|안드로이드 컴포넌트에 내장 지원을 제공. 안드로이드에 특화됨.|
|스코핑|수동 설정 및 커스텀 어노테이션 필요.|안드로이드 생명주기에 클래스와 밀접하게 통합된 사전 정의 된 범위를 제공.|
|코드 단순성|복잡한 구조에서 더 세밀하게 사용할 수 있는 유연함. 다만 개발자가 모두 수동으로 정의 필요.|보일러 플레이트 코드를 추상화하여 DI 설정의 복잡성을 줄여 사용이 더 쉬움.|
|사용 사례|복잡하고 커스텀된 의존성 주입 그래프가 필요한 프로젝트|사용 편의성과 안드로이드 컴포넌트와의 통합에 중점을 둔 안드로이드 프로젝트|


### 📑 Dagger2
- 안드로이드 및 JVM 환경을 위한 정적 컴파일 타임 기반의 의존성 주입 라이브러리
- 객체 생성 관리, 의존성 자동 제공으로 모듈성을 개선하고 앱 테스트를 용이하도록 설계됨.
- 컴파일 타임에 코드를 생성, 리플렉션에 기반한 DI 프레임워크에 비해 더 나은 성능 보장.
- 어노테이션을 사용하여 의존성을 선언, 요청


### 📑 Hilt
- Dagger2 위에 구축된 안드로이드 전용 의존성 주입 라이브러리.
- 생명주기와 밀접한 관련이 있는 클래스에 스코프가 지정된 사전 정의된 컴포넌트를 제공하여 Dagger를 안드로이드 프로젝트에 통합하는 프로세스를 전체적으로 단순화함.
- 어노테이션을 제공하여 DI 설정을 간소화, 많은 보일러 플레이트 코드 제거.
- 의존성 생명주기 관리 가능.


### 📖 Question
1. Dagger2와 비교하여 Hilt는 DI를 어떻게 단순화했나요?
2. 안드로이드 앱에서 Hilt를 사용하는 것의 정점은 무엇인가요?
3. Hilt에서 스코핑 어노테이션이 내부적으로 어떻게 작동하는지 매커니즘을 설명하고, 앱 내 의존성 수명을 어떻게 관리하나요?
