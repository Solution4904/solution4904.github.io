# 💡 3. 트러블슈팅 & 해결 방법
- 일정 등록 시 한 번, 매 주, 매 달 반복 등록시키는 기능을 어떻게 구현해야 할 지 생각하다가 물리적으로 해당되는 모든 날짜에 등록하는 방법을 처음 생각했었다. 알아보니 수백, 수천개의 데이터를 한번에 등록시키는 방법이어서 앱에 무리가 가지 않을까 했는데 생각보다 ms 단위의 지연 밖에 되지 않는다고 해서 구현해보려 했는데, 일정을 수정하게 될 경우가 문제였다. A라는 일정을 매 주 반복 등록시키고 후에 A라는 일정을 수정했을 경우에는? 그러면 A의 모든 일정을 찾아서 수정해야하는데 어떻게 처리해야할까 생각했다. DB를 사용했다면 SQL로 충분히 할만할 것 같았지만 현재 앱에서의 데이터 저장/불러오기는 모두 SharedPreference를 사용한 json 데이터였다. 데이터 방식을 ROOM으로 교체할까도 생각했지만 일단은 1차원적인 방식으로 개발하려고 했기 때문에 논외였다. 결국 여러 방향으로 연구해본결과 실제 일정 데이터는 한개만 등록시키고 해당 일정이 등록되어야하는 날짜 데이터들을 갖고있게 한 뒤 그 날짜 데이터를 사용해서 캘린더에 표현시키는 일종의 인스턴스 방식으로 구현했다. 여러모로 구조가 복잡해졌고 도저히 생각나지 않는 부분들은 AI의 힘을 빌려 해결했다.
