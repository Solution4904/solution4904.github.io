# 💡 2. 알게 된 점
- BindingAdapter 사용 방법
- RecyclerView의 ViewHolder를 쓰임에 따라 각각 다른 View를 Create해서 Binding해서 사용하는 개발 방식을 알아냄
- 단순 Log로 로깅하면 어떤 부분에서 발생한 로그인지를 알 수 없어서 답답할 때가 있었는데 Stack Trace로 어떤 부분의 Log인지 나타나게 하는 방법을 알아냄

# 💡 3. 트러블슈팅 & 해결 방법
- MVVM 패턴 적용 중 ViewModel을 역할게 맞게 사용하는 게 굉장히 어려웠다. 패턴이 왜 사용되어지고 있고 각각 어떤 역할을 해야하는지에 대해 더 심층적으로 조사하고 사용하려고 노력했다.
- 리사이클러뷰에 어댑터까지 로그로는 모두 정상적이었는데 나타나지 않는 문제가 있었다. 계속 어댑터에 데이터로 들어가는 리스트의 아이템들이 정상적으로 들어가지 않아서 발생하는 문제로만 생각하고 해결하려고 했는데 나중에 보니 ViewModel을 제대로 사용하고 있지 않았던 상태에서 정상적으로 적용하려고 코드를 많이 바꾸는 과정에서 리사이클러뷰에 LayoutManager가 사라져서 였다. 단순한 문제였는데 너무 전체를 보지 않는 것 같다. 문제가 발생했을 때 더 시야를 넓게 가지는 연습이 필요할 것 같다.
<br><br><br>
<!-- ---------- -->



# 💡 4. 개선 사항
- Model과 상호작용하는 기능들을 ViewModel을 통하도록 코드 개선 필요.
- 리사이클러뷰에서 스케줄이 할당 방식일 때 할당 아이콘을 클릭하면 리스트 전체가 다시 그려지는 중. 예상하기로는 리사이클러뷰의 어댑터가 갖고 있는 데이터 리스트를 옵저빙하다가 데이터가 바뀌어서 이벤트가 발생할 경우 notifydatasetchanged로 갱신해서 발생하는 문제로 보임. 변경된 데이터만 갱신하는 방식으로 개선 필요.
